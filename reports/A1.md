## Secret safety
make_sdl.py reads .env.clickhouse only to compare: it refuses (exit 1, message names only the key) if any value of 4+ chars appears in the SDL. Tested: with a scratch env file containing `CLICKHOUSE_USER=cairn_ro` it printed `REFUSING: a value from .env.clickhouse (key CLICKHOUSE_USER) appears in the SDL; not writing.` rc=1. With the real file, a check of all three values against deploy.yaml gave `[False, False, False]`. Pavan types real host/password into the Console only; read-only user cairn_ro, dropped afterwards (CHECKLIST steps 1, 9).

## Size limits
Akash manifest/command/env size limits: UNVERIFIED (web search found nothing Akash-specific). Linux per-arg limit is 128 KB so the 9.8 KB arg is fine at OS level; the A2 scanner SDL (5.7 KB) is the only size known to be accepted in this project (and was not deployed either). Kubernetes object cap ~1 MB, well above. 
Fallback if Console/provider rejects: (a) split the base64 into 3-4 env vars (`B1..B4`, ~3 KB each) and use `echo $B1$B2$B3$B4 | base64 -d | gunzip > ...`; no publishing needed. (b) fetching from a public URL would require publishing the file: ONLY with Pavan's approval. (c) Last resort: local docker run of the same command.

## check_ro_user.sh
Takes CLICKHOUSE_URL, CLICKHOUSE_RO_USER, CLICKHOUSE_RO_PASSWORD from the environment, sends header auth via `curl -K -` (stdin config, password not in argv). Checks SELECT on both tables returns 200, and INSERT/DROP/CREATE return HTTP >=400. Only ran against a dead address (`127.0.0.1:9`): output `HTTP 000`, every check FAIL, exit 1 (so connection failures are not mistaken for "refused"; I fixed an early bug where they were). Never run against real ClickHouse (not allowed); UNVERIFIED against a live server.
