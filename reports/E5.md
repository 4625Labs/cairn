# E5 Event log

## Built (all in events/)
- schema.sql: ClickHouse `cairn_events`, MergeTree, ORDER BY (card_id, ts), PLAN.md columns.
- queries.sql: the four read-only queries (incident_groups, incident_evidence, spread, ignored). Same SQL runs on ClickHouse and SQLite.
- cairn_log.py (stdlib): `append`, `incident --window 10m`, `spread --card ID [--recent 3m] [--live]`, `ignored`, `demo-seed [--fresh]`.
- demo.db: synthetic DEMO data (every detail prefixed "DEMO:", plus a `demo_label` table). Use `--demo` to read it. Never mixed with cairn.db.

## Run
    python3 events/cairn_log.py append '{"kind":"finding","card_id":"unvalidated-network-input","repo":"esptember","file":"day22/hub/server.c","line":88,"actor":"semgrep","tool":"semgrep","verdict":"open","detail":"strcpy"}'
    ... | python3 events/cairn_log.py append          # JSON lines on stdin
    python3 events/cairn_log.py --demo incident --window 10m
    python3 events/cairn_log.py --demo spread --card unvalidated-network-input
    python3 events/cairn_log.py --demo ignored
Backend order: --db/--demo (SQLite) > CLICKHOUSE_URL (+ CLICKHOUSE_USER/CLICKHOUSE_PASSWORD env, sent as headers only, URL with embedded creds refused, plain http only for localhost) > ClickHouse answering on 127.0.0.1:8123 > events/cairn.db. CAIRN_BACKEND=sqlite forces SQLite. No remote contact unless CLICKHOUSE_URL is set.

## Validation
Whole batch rejected before any write: kind in the 8 allowed; card_id ^[a-z0-9][a-z0-9_.-]{0,63}$; repo/actor/tool <=100-200, file <=500, detail <=2000; line int 0..10M; verdict ^[a-z0-9_.-]{0,32}$; ts ISO-8601; unknown fields, control chars, >16KB lines, >1000 rows rejected. Tested: bad kind, bad card_id (`X; DROP`), negative line, extra field all exit 2 with nothing written.
Append-only: code only issues INSERT/SELECT; SQLite also has triggers; `delete from cairn_events` was refused ("append-only"). ClickHouse has no equivalent guard besides our code (give the CH user INSERT/SELECT-only grants for real enforcement).
