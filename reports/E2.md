## CLI
`agent-dial ask [flags] "question" [option ...]` blocks, prints the chosen option, exit 0.
Flags: `--options "A,B,C"` (default Yes,No; also positional extras or repeated `--option`), `--approve` (Allow/Deny, key `decision`, exit 1 on Deny), `--multi`, `--key`, `--id`, `--name`, `--timeout S`, `--connect-timeout S` (default 3), `--json`.
Exit codes: 0 answered, 1 denied, 2 usage, 3 no hub/dial, 4 timeout, 5 closed without answer.
Also: `event <turn.started|turn.done|turn.error|summary|bye> [--id --name --harness --cwd --caps --ttl --text --message]`, `claude <Event>` (stdin hook JSON; always exit 0), `install-claude`, `status`, `release`, `pair`, `forget`, `wifi [--ssid]`, `sim [--auto allow|deny|first|last|text] [--delay ms]`.

## Hardening (input validation)
Every adapter line is parsed in try/catch and must be a plain object with string `t` (null, numbers, arrays, wrong-typed fields are dropped and counted); lines over 64 KB are skipped; max 64 connections, 16 sessions, 8 pending questions per session / 32 total. Ids are printable ASCII without spaces (overlong keeps the tail), all text strips control/bidi chars and is capped by codepoints, caps are whitelisted. Device frames: oversize/corrupt handled by the codec; JSON must be an object; hello fields (mac, ip, key) are regex-validated; answers only for open questions, only listed keys, string values only, approvals only `Allow`/`Deny`, and only if the session declared the capability. Trust: a connection can act only on sessions it owns; a live non-ttl session cannot be taken over by another connection (ttl hook sessions can be re-claimed, by design); adapters cannot send device-only types; `raw` is limited to `diag.*`, `toast`, `focus`, `ping`. The socket is mode 0600 in a 0700 dir; the hub opens no network listener. Residual: any same-user process can claim a ttl session id.
