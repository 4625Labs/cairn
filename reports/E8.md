# E8: gate hardening (patch hygiene) in cairn/fix/run.py

## What changed
`cairn/fix/run.py` (normal and `verify` modes share `gate_phase`) now runs step `[4b] patch hygiene` before the gate:
1. Scope rule: unified diff parsed per file/hunk (old line numbers kept). Every REMOVED or MODIFIED line must match a per-card allowlist (`ALLOW_REMOVE`): portal.c = the `char option[N];` declaration and the two lines of the unescaped `snprintf(option, ... "<option>%.32s</option>", (const char *)aps[i].ssid);`; day-01 manifest = only the `waveshare/esp32_s3_touch_amoled_1_8: "^2.0.3"` line. Pure additions in those files pass. Any change (removal, modification or addition) to a file not on the list is out of scope. Each offence is printed as `file:line: an unrelated line was CHANGED: before "..." / after "..."` (or DELETED).
2. Identifier check (C files): identifiers on added lines (`//` comments ignored) that are new versus the original (target/seeds) and within edit distance 1 (names 4-6 chars) or 2 (7+) of an original identifier are flagged (eSP_ERROR_CHECK, nvo_erase_all, portal_submit_cb__t, celect, sizeoff). Also flags control/non-ASCII characters in added lines: PR #1's "httpdstart" is really `httpd\x1fstart` (a 0x1F byte), found by this.
3. `pr_gate` event carries the reasons (detail, first 1500 chars; verdict block).
4. Gate line: `GATE: BLOCK (rescan_clean=.. seed_left=.. new=.. test_pass=.. hygiene=False, unrelated_changes=N)`; N = scope + typo findings. Details are printed under `[4b]`.
No existing check was weakened (hygiene is an extra AND in the verdict).

Limits (also in the source comment): additions are not scoped (rely on re-scan and unit test); the allowlist is regex on trimmed line text, so an allowed line changed into something odd is accepted (typos in it are caught only by the identifier check); identifiers under 4 chars ignored (`s[2]`->`o[2]` caught by scope only); a legitimate new identifier 1-2 edits from an old one is a false positive (blocks); a typo landing on another existing identifier is invisible. Original comes from target/seeds, so `--keep-work` runs compare against seeds, not the kept tree.

## html_escape unit-test edge case
`FAIL: tiny buffer holds whole entities only` is a REAL bug in the PR's helper, not a test problem: its loop `while (*esc && o < out_len - 1) out[o++] = *esc++;` copies part of an entity when the buffer is nearly full (`&l` for `&lt;`), producing a truncated entity. The test is correct and left unchanged. I did not edit the PR's code (it is the agent's patch); the fix for the agent is: only copy an entity if `o + strlen(esc) < out_len`, else stop. Cairn's own HELPER already does this. The PR's extra `;` -> `&#59;` case is harmless but beyond the card (and is a pure addition, so scope allows it).
